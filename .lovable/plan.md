## الوضع الحالي المؤكد

- `get_stock_shortages()` تعتمد بالفعل على `get_active_invoice_reservations()` كمصدر وحيد، وترجع الآن `needed_qty`, `stock_quantity`, `incoming_qty`, `net_shortage` + مصفوفة `invoices` تحتوي رقم الفاتورة/العميل/الحالة/`delivery_status`.
- تنبيه "متتبع المخزون" في `/in-transit` يحسب محليًا بدل استدعاء نفس الـRPC، فبيحصل احتمال اختلاف طفيف في العد.
- صفحة `stock-shortages.tsx` بتعرض الفواتير لكن بدون فلترة بحالة الفاتورة/التسليم، وبدون تفكيك مصادر النقص (المخزون / القادم / الفواتير).

## الخطة

1. **توحيد مصدر الحقيقة (DB)**
   - أضيف RPC واحدة `get_inventory_shortage_alerts()` ترجع نفس صفوف `get_stock_shortages()` + حقول إضافية لكل منتج:
     - `sources`: تفصيل لكل فاتورة (رقم، عميل، `status`, `delivery_status`, `reserved_qty`, `delivered_qty`, `remaining_qty`, `created_at`).
     - `incoming_pos`: قائمة أوامر الشراء المتوقعة (`po_number`, `expected_qty`, `expected_date`).
     - `coverage`: `from_stock`, `from_incoming`, `shortfall` (نفس منطق `fulfillment-engine`).
   - أعدّل `get_stock_shortages()` لتصير غلاف رفيع فوق الجديدة (نفس الأعمدة الحالية) حتى لا يتأثر أي مستهلك.

2. **متتبع المخزون يستدعي نفس الـRPC**
   - في `src/routes/in-transit.tsx` أستبدل الحساب المحلي لبطاقة "تنبيهات ذكية للحجوزات" باستدعاء `get_inventory_shortage_alerts()`، فيبقى العدد "نقص" و"بانتظار وصول" مطابق تمامًا لتقرير النواقص.
   - أزيل أي مطابقة/رياضة إضافية على العميل.

3. **فلاتر حالة الفاتورة داخل تقرير النواقص**
   - في `src/routes/stock-shortages.tsx` أضيف شريط فلاتر (Checkboxes):
     - الحالة المالية: مفتوحة (`pending/completed`) / مدفوعة جزئيًا / مغلقة / أرشيف.
     - حالة التسليم: `pending` / `partial` / `delivered`.
   - الفلاتر تطبّق على مصفوفة `sources` لكل صف؛ لو الصف بعد الفلترة مبقاش فيه أي فاتورة، يتخفي.
   - الافتراضي = "فواتير نشطة غير مسلّمة بالكامل" (المطابق للسلوك الحالي).

4. **عرض تفاصيل المصادر لكل عنصر**
   - كل صف في التقرير يبقى قابل للفتح (Expand) ويعرض:
     - **الفواتير**: رقم، عميل، تاريخ، حالة الفاتورة، حالة التسليم، محجوز، مسلّم، متبقّي (شارة ملوّنة).
     - **بانتظار الوصول**: أوامر الشراء المرتبطة + الكميات + التواريخ المتوقعة.
     - **المخزون والحركة**: آخر عمليات `inventory_logs` المؤثرة (sale/void/edit) للمنتج (آخر 10).
   - أعلى الصف: شارات موجزة "من المخزون X / من القادم Y / نقص صافي Z".

5. **تحقّق نهائي بعد التنفيذ**
   - عدد بطاقات التنبيه في `/in-transit` == عدد صفوف تقرير النواقص (بنفس الفلتر الافتراضي).
   - مجموع `remaining_qty` من مصادر كل صف == `needed_qty`.
   - `net_shortage == max(0, needed_qty - stock - incoming)` لكل صف.
   - لا تظهر فواتير `draft/voided/cancelled/archived` أو `delivered` بالكامل داخل أي مصدر.

## الملفات المتأثرة

- Migration جديد: `get_inventory_shortage_alerts` + تعديل `get_stock_shortages`.
- `src/routes/stock-shortages.tsx` — فلاتر + Expand مع تفاصيل المصادر.
- `src/routes/in-transit.tsx` — قسم "تنبيهات ذكية للحجوزات" يستدعي الـRPC الموحّدة.

## النتيجة المتوقعة

- رقم واحد ثابت للنقص عبر كل الصفحات.
- تقدر تختار حالات فواتير معينة وتعيد التحقق فورًا.
- لكل منتج ناقص هتشوف بالضبط: أي فواتير سبّبت النقص، أي POs قادمة تغطيه جزئيًا، وأي حركات مخزون حصلت.
