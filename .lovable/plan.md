## الهدف
إضافة **وزن لكل منتج** واستخدامه لتوزيع تكلفة **الشحن** على المنتجات حسب الوزن الفعلي، بينما تبقى الجمارك والضرائب والمصاريف الإضافية موزّعة حسب **قيمة المنتج بالدولار** — بحيث يصبح صافي الربح والهامش في صفحة الأرباح دقيق حسب حجم كل منتج.

## القاعدة الحسابية الجديدة (لكل PO)
لكل سطر منتج داخل الـ PO:
```
weight_share = (qty × unit_weight_kg) / Σ(qty × unit_weight_kg) للـ PO
value_share  = line_total_usd / Σ line_total_usd للـ PO   ← الحالي
```
التوزيع:
- **الشحن (shipping)** → `weight_share` (جديد)
- **الجمارك (customs)** → `value_share`
- **الضرائب (taxes)** → `value_share`
- **إضافي (other)** → `value_share`

Fallback: لو مافيش أوزان مسجلة في الـ PO كله → الشحن يرجع يتوزع بـ `value_share` (سلوك النظام الحالي، فلا شيء ينكسر بأثر رجعي).

## التغييرات

### 1) قاعدة البيانات (migration)
- `products.weight_grams numeric` (nullable — الوزن بالجرام، يقبل كسور للجرامات الدقيقة).
- `purchase_order_items.unit_weight_grams numeric` (snapshot عند إنشاء/استلام السطر، حتى لو غيّرت وزن المنتج لاحقاً ما يتأثرش تاريخ الـ PO).
- تحديث RPC `get_product_cost_book` لاستخدام قاعدة التوزيع الجديدة (weight للشحن، value للباقي) مع Fallback.

### 2) صفحة المنتجات (`src/routes/products.tsx`)
- حقل **الوزن** في فورم إضافة/تعديل المنتج: إدخال رقمي + اختيار الوحدة (**جرام / كيلوجرام**) — يُحفظ داخلياً كجرامات.
- عمود اختياري "الوزن" في جدول المنتجات (يعرض kg إذا ≥ 1000g، غير ذلك g).

### 3) PO Builder (`src/routes/purchase-orders.tsx`)
- عند إضافة منتج للـ PO: نسخ `weight_grams` تلقائياً إلى `unit_weight_grams` للسطر.
- عرض عمود "الوزن/الوحدة" و"إجمالي الوزن للسطر" داخل جدول بنود الـ PO.
- سطر ملخّص "إجمالي وزن الشحنة" في الفوتر (kg).
- إمكانية تعديل الوزن يدوياً لسطر معين (لو تختلف الشحنة الفعلية عن المسجل).

### 4) صفحة الأرباح (`src/routes/profits.tsx` + `src/lib/po-cost-history.ts`)
- الـ RPC المُحدَّث يرجّع نفس حقول landed cost لكن بحسبة أدق → لا تغيير في هيكل الـ types.
- في لوحة "تاريخ التكلفة عبر أوامر الشراء": إضافة عمود صغير "وزن الوحدة" ورمز توضيحي على عمود الشحن يشرح "موزَّع حسب الوزن".
- Landed WAC تلقائياً يصبح أدق (المنتجات الثقيلة تحمل نصيب أكبر من الشحن، الخفيفة أقل) → صافي الربح والهامش لكل فاتورة في نفس الصفحة يتحدّث تلقائياً بدون كود إضافي (الحساب مبني فوق نفس الـ RPC).

### 5) اختبارات
تحديث `src/lib/po-cost-history.test.ts` بحالات:
- PO بأوزان مختلفة → الشحن يتوزّع بالوزن، الجمارك بالقيمة.
- PO بدون أوزان (Fallback) → السلوك الحالي بدون تغيير.
- منتج ثقيل + رخيص vs منتج خفيف + غالي → التحقق أن الشحن انعكس بالوزن.

## ملاحظات
- الوحدات: نخزّن جرامات داخلياً (numeric) لتفادي أخطاء تقريب الكيلو، والعرض يتحوّل تلقائياً (g/kg).
- لا يتغير شكل صفحة الأرباح ولا الفواتير — فقط الأرقام تصبح أدق تلقائياً بمجرد إدخال الأوزان.
- المنتجات القديمة اللي مالهاش وزن هتبقى فاضية → لازم تدخل الأوزان لتفعيل توزيع الشحن بالوزن (وإلا يعمل Fallback للقاعدة القديمة).
