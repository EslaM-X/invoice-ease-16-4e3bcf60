
# خطة الإصلاح الشامل — أوامر الشراء + محاضر الاستلام + المخزون

أنت بتطلب 7 حاجات مترابطة. هكتب الخطة بترتيب التنفيذ، وكل بند مربوط بالملف اللي هتتغير فيه.

---

## 1) تعديل/إضافة منتجات لأمر شراء موجود بدون لمس محاضر الاستلام

**المشكلة الحالية:** أي تعديل على الـ PO بيرجعك للبداية أو بيمسح محاضر الاستلام.

**الحل:**
- زرار **"تعديل البنود"** داخل `po-tracker-dialog.tsx` بدون إغلاق المتابعة.
- إضافة بند جديد = `INSERT INTO purchase_order_items` فقط — محاضر الاستلام الحالية تفضل سليمة.
- تعديل سعر/كمية بند موجود = `UPDATE` مع منع إنقاص الكمية لأقل من المستلم فعلاً (validation).
- حذف بند = يُسمح به فقط لو `received_qty = 0`.
- كل تعديل يتسجل في `audit_log` مع before/after.

## 2) تواريخ قابلة للتعديل + تعديل بنود الدفعة بعد إنشائها

**المشكلة:** دفعة D1#1 بتاريخ ثابت ومش بتعديل.

**الحل:**
- إضافة عمود `receipt_date` (timestamptz, default now) لجدول `po_receipts` — قابل للتعديل بواسطة الأدمن.
- RPC جديدة `update_po_receipt_batch(receipt_id, p_date, p_items)`:
  - تعدل التاريخ.
  - تضيف/تعدل/تحذف بنود الدفعة.
  - تعيد حساب `inventory_logs` المرتبطة (delta = الجديد − القديم).
  - تسجل كل خطوة في audit log.
- UI: زرار قلم بجوار كل badge `D1#1` يفتح dialog تعديل (تاريخ + بنود).

## 3) فلاتر بحث (كولكشن، لون، سيريال، صورة) داخل نافذة الاستلام

**في `po-tracker-dialog.tsx` (popup تسجيل دفعة):**
- شريط فلاتر: بحث نصي (اسم/سيريال) + select للكولكشن + select للون + toggle "السيريالات الناقصة فقط".
- صور thumbnails أكبر بجوار كل صف.
- نفس الفلاتر في صفحة `delivery-receipts.index.tsx`.

## 4) Default = الكل صفر + أزرار "تحديد الكل بالكمية الكاملة" / "كمية موحدة"

- عند فتح dialog الاستلام: كل القيم = 0 (مش الكمية المتبقية).
- زرار **"تحديد الكل بالكمية الكاملة"** = يملأ كل صف بـ `remaining`.
- زرار **"تطبيق كمية موحدة"** + input رقم = يحط نفس الرقم في كل صف (clamped على remaining).
- زرار **"تصفير الكل"**.

## 5) حذف PO + رجوع المخزون بدقة

**الحل:**
- RPC `delete_po_with_inventory_rollback(p_po_id)`:
  1. تجيب كل `po_receipts` للـ PO.
  2. لكل دفعة: تنشئ `inventory_logs` عكسية (`-qty`) + تنفذ `back-deduction reversal` للفواتير التاريخية اللي اتأثرت.
  3. تحذف `po_receipt_items` → `po_receipts` → `purchase_order_items` → `purchase_orders`.
  4. كله في transaction واحدة. لو في فاتورة باعت المنتج بالفعل = ترفض الحذف وترجع رسالة واضحة.
- زر "حذف PO" في `purchase-orders.tsx` (admin only) مع تأكيد مزدوج.

## 6) فحص دقة المخزون — السبب الجذري للأرقام الغلط

**التشخيص اللي ظهر من اللوج بتاعك:**
```
QUATRO WALL MOUNTED TWO HOLE BASIN MIXER
+5  PO-2026-0001 استلام دفعة #1   (15 مايو)
-18 manual: صيي                   (17 مايو)
-2  manual: ييي                   (17 مايو)
+1  PO-2026-0001 استلام دفعة #1   (17 يونيو)  ← دفعة ثانية لنفس الـ PO!
-3  PO-2026-0004 عكس استلام        (17 يونيو)
```
**في مشكلتين:**
- (أ) فيه إدخالات manual بكميات سالبة غير منطقية (-18, -2) — دي مصدر الأرقام الغلط، مش الكود.
- (ب) "استلام دفعة #1" اتسجل مرتين لنفس الـ PO بفرق شهر — يعني فيه bug في `apply_po_receipt` بيسمح بإعادة الإدخال.

**الحل:**
- إضافة `UNIQUE(po_id, receipt_number)` على `po_receipts`.
- صفحة **مراجعة المخزون** (`/inventory-reconcile`) موجودة فعلاً — هضيف فيها زرار "إعادة بناء من المصدر" (rebuild stock from inventory_logs المعتمدة فقط) مع تقرير الفروق.
- إصلاح `apply_po_receipt_with_back_deduct` لتمنع double-apply.

## 7) إصلاح "تقرير تسوية محاضر الاستلام التاريخية" + خطأ زر "تم"

- هصلح الـ RPC `list_pending_back_deductions` (بيرجع خطأ حاليًا).
- هخلي صفحة `back-deduction-report.tsx` تعرض: محاضر مكتملة، معلقة، فروقات بالعدد، مع زر "تنفيذ الخصم" يشتغل صح.
- زر **تنزيل CSV** للتقرير.

## 8) ملخص مطابقة PDF مع زر تنزيل تقرير

في `po-pdf-receipt-dialog.tsx`:
- بعد parse: جدول تفصيلي يعرض: ✓ مطابق / ⚠ زيادة (مع الفرق) / ✗ مفقود + serial diffs.
- زر **"تنزيل تقرير CSV"** يصدّر الكل.

## أولوية التنفيذ

1. **عاجل:** RPC حذف PO + UNIQUE constraint + إعادة بناء المخزون (يحل مشكلة الأرقام الغلط)
2. تعديل بنود PO وبنود الدفعة + تواريخ
3. فلاتر + default-0 + أزرار جماعية
4. إصلاح تقرير التسوية
5. تقرير مطابقة PDF + CSV

## أسئلة قبل ما أبدأ

- **سؤال 1:** لما أحذف PO وفيه منتجات اتباعت في فواتير فعلاً — أرفض الحذف، ولا أسمح بالحذف وأخلي الفواتير بدون رصيد (مع تحذير)؟
- **سؤال 2:** الإدخالات اليدوية السالبة الغريبة (`-18 manual: صيي`) — تحب أحذفها من قاعدة البيانات دلوقتي عشان الأرقام ترجع صح، ولا أسيبها وأخليك تراجعها يدوياً في صفحة "إعادة بناء المخزون" الجديدة؟

أكدلي على الإجابتين دول وأبدأ التنفيذ على طول.
